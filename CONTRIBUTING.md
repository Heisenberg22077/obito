# Contributing to Data Science & AI Roadmap

Thank you for your interest in improving this curriculum! This document explains how to contribute effectively.

## 🎯 Ways to Contribute

### 1. Report Issues
- **Broken links**: Use the [Bug Report](.github/ISSUE_TEMPLATE/bug-report-template.md) template
- **Content problems**: Missing prerequisites, outdated resources, unclear explanations
- **Accessibility issues**: Content that isn't accessible to all learners

### 2. Suggest Improvements
- **New resources**: Better courses, books, or tutorials
- **Project ideas**: Real-world projects that demonstrate skills
- **Clarifications**: Explanations that could be clearer
- **Track updates**: Career path adjustments based on market changes

Use the [Feature Request](.github/ISSUE_TEMPLATE/feature-request.md) template.

### 3. Contribute Content
- **Resource reviews**: Evaluate and recommend new learning materials
- **Module expansions**: Add depth to existing modules
- **Translations**: Help localize content for non-English speakers
- **Notebooks**: Create reference Jupyter notebooks for key concepts

Use the [Content Contribution](.github/ISSUE_TEMPLATE/content-contribution.md) template.

## 📋 Contribution Guidelines

### Before Submitting

1. **Search existing issues** to avoid duplicates
2. **Test all links** you're adding or modifying
3. **Verify resource quality**:
   - Author credibility and expertise
   - Currency (preferably updated within 2 years)
   - Alignment with module objectives
   - Accessibility (captions, free access)

### Quality Standards

#### For Resource Recommendations
- ✅ Must be high-quality and reputable
- ✅ Should have stood the test of time or be from trusted sources
- ✅ Free or clearly marked paid options
- ✅ Accessible format (or alternatives provided)

#### For Projects
- ✅ Clear learning objectives
- ✅ Realistic scope (can be completed in stated time)
- ✅ Includes evaluation criteria
- ✅ Demonstrates multiple skills

#### For Content Changes
- ✅ Evidence-based claims
- ✅ Cites sources appropriately
- ✅ Maintains neutral, inclusive tone
- ✅ Follows existing formatting conventions

### Pull Request Process

1. **Fork the repository**
2. **Create a feature branch** (`git checkout -b feature/your-improvement`)
3. **Make focused changes** (one concern per PR)
4. **Test locally** if possible
5. **Write clear commit messages**
6. **Submit PR** with description of changes and rationale

### Review Timeline

- We aim to review contributions within 7 days
- Be patient and open to feedback
- Maintain respectful discourse

## 🌍 Translations

We welcome translations to make this curriculum accessible globally.

### Translation Process
1. Check if translation already exists
2. Create language-specific directory (e.g., `translations/es/`)
3. Translate core files maintaining structure
4. Note any cultural adaptations needed
5. Submit as PR with language tag

### Translation Guidelines
- Keep technical terms consistent
- Preserve links and references
- Note region-specific considerations
- Include translator notes where context differs

## 🔍 Link Verification

Before submitting:
- Test all URLs manually
- Ensure they're not behind paywalls (unless noted)
- Verify content matches description
- Check accessibility features

Our automated link checker runs weekly, but human verification is invaluable.
